# Frontend Specification (HTML/JS Client)

## 1. Основна цел
Frontend-ът е самостоятелен HTML файл, който служи като терминал за симулация на търговия. Той не се свързва директно с Binance, а комуникира изцяло с нашия Python сървиз. Целта е потребителят да може да отваря няколко таба, да купува/продава, да мести TP/SL линии и да вижда в реално време как се променя неговият портфейл.

## 2. Архитектура на JavaScript
Целият код е в един `<script>` таг. Няма външни зависимости освен `lightweight-charts`.

### 2.1. Глобално състояние (`appState`)
Всички данни за портфейла се пазят в един обект в паметта:
```javascript
const appState = {
  capital: 500,        // Общ капитал в USDT
  posPct: 10,          // Процент от капитала за 1 позиция
  maxPos: 3,           // Максимален брой отворени позиции
  tabs: [],            // Масив с обекти за всеки таб (символ, позиция, история)
  activeTabId: null,   // ID на текущо активния таб
  realizedPnl: 0       // Натрупана реализирана печалба
};
```

### 2.2. Управление на табове
- Всеки таб има уникален `id` (timestamp), `symbol` (напр. BTCUSDT), `position` (ако има отворена) и `history` (лог на сделките).
- При превключване на таб (`switchTab`), скриптът:
  1. Изчиства текущата графика (`chartObj.removeSeries()`).
  2. Прави `fetch` към Python сървиза за историята на новата двойка.
  3. Изчаква 500ms (за да се рендира графиката) и възстановява линиите, ако в този таб има отворена позиция.

### 2.3. Комуникация с Python сървиза
- **За история:** `fetch('http://127.0.0.1:8080/api/history/BTCUSDT')` -> връща масив от 1m свещи.
- **За реално време:** Една единствена WebSocket връзка към `ws://127.0.0.1:8080/ws/stream`.
  - Сървизът изпраща данни за **всички** двойки.
  - Frontend-ът трябва да филтрира: `const tab = appState.tabs.find(t => t.symbol === msg.symbol)`. Ако табът е активен, обновява графиката; ако не е, само обновява `currentPrice` в паметта.

## 3. Графичен интерфейс (`lightweight-charts`)
- **Версия:** `4.1.1` (строго фиксирана).
- **Създаване:** `chartObj.addCandlestickSeries(...)`.
- **Линии (Entry, TP, SL):** Създават се чрез `candleSeries.createPriceLine()`. 
- **Drag & Drop:** Линиите се местят чрез комбинация от `mousedown`, `mousemove` и `mouseup`. 
  - Скриптът изчислява координатите на мишката спрямо цената.
  - Ако потребителят хване TP линията, той не може да я плъзне под Entry цената (за Long позиция).

## 4. Логика на позициите
- **Отваряне:** 
  - `sizeUSD = capital * (posPct / 100)`
  - `qty = (sizeUSD * (1 - FEE_RATE)) / currentPrice`
  - `sl = currentPrice * (1 - 0.0010)` (за Long)
  - `tp = currentPrice * (1 + 0.0030)` (за Long)
- **Затваряне:**
  - `rawPnl = (exitPrice - entryPrice) * qty`
  - `totalFees = feeOpen + feeClose`
  - `netPnl = rawPnl - totalFees`
  - `capital += netPnl`

## 5. BPS Overlay (Текст върху графиката)
Тъй като `lightweight-charts` не позволява лесно добавяне на текст между линии, използваме HTML `<div>` елементи с `position: absolute`.
- Те се позиционират с `top: midTPY + 'px'` (където `midTPY` е средата между Entry и TP).
- Обновяват се на всеки 100ms чрез `setInterval(updateBpsOverlay, 100)`, за да следват зума и скрола на графиката.

## 6. Debug функция
Бутонът "📋 Debug Log" в горния десен ъгъл събира целия `appState` (капитал, табове, позиции, история) и го копира като JSON в клипборда. Това е критично за дебъг, защото позволява на разработчика да види какво се случва в "мозъка" на приложението, без да се разчита на снимки на екрана.
