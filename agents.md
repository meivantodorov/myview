# Инструкции за AI Агенти и разработчици (AGENTS.md)

Този документ описва строгите правила за комуникация, управление на версиите и работния процес при разработката на **Binance Micro-Terminal**. Всеки AI агент, който генерира код за този проект, **ТРЯБВА** да спазва тези инструкции.

## 1. Работен процес и формат на отговорите (Критично важно!)
Потребителят използва два PowerShell скрипта, за да копира и поставя файлове директно от чата в терминала, без да отваря редактор. 
- `paste.bat` – взима съдържанието от клипборда и презаписва посочения файл.
- `copy.bat` – копира съдържанието на файл в клипборда (за проверка).

Във фазата, когато агентът трябва да промени даден файл, отговорът **ЗАДЪЛЖИТЕЛНО** трябва да следва този точен формат:

### 📄 Файл: `път/до/файла.разширение`

Стъпка 1 (Команда за paste):
```cmd
.\scripts\paste.bat .\път\до\файла.разширение
```

Стъпка 2 (Код за копиране):
```javascript
// Целият код на файла (без съкращения)
```

*(Ако има няколко файла за промяна, те се описват един след друг в този формат).*

### 🛠️ Финална стъпка (Rebuild)
След като всички файлове са поставени, агентът винаги трябва да завършва с командата за презареждане на Docker:
```cmd
docker-compose up -d --build
```

## 2. Управление на версиите и хешове
Системата има вградена проверка за цялост (Integrity Check), за да се уверяваме, че файловете в браузъра съвпадат с тези, генерирани от агента.

- **Версия:** При всяка промяна по Frontend-а (HTML или JS), версията във файл `client/js/state.js` (променлива `VERSION`) трябва да се вдига (напр. от `v7.3` на `v7.4`).
- **Хеш:** В долния ляв ъгъл на интерфейса се показва SHA-256 хеш на клиента (`Cz ...`) и на сървъра (`B: ...`).
- **Debug Log:** Бутонът "📋 Debug Log" копира JSON с текущия хеш, версия, настройки и отворени позиции. Потребителят изпраща този лог при проблем, за да може Агентът да провери дали файловете са синхронизирани.

## 3. Управление на Docker сервизите 
Проектът работи изолирано в Docker контейнери (Python Backend + Nginx Frontend). Управлението става през `.bat` файлове в папка `scripts/` (или директно през терминала).

- **Стартиране (и билдване):**
  ```cmd
  docker-compose up -d --build
  ```
  *(Или `.\scripts\start_service.bat`)*

- **Спиране на сервизите:**
  ```cmd
  docker-compose down
  ```
  *(Или `.\scripts\stop_service.bat`)*

- **Рестартиране (без ребилд):**
  ```cmd
  docker-compose restart
  ```
  *(Или `.\scripts\restart_service.bat`)*

- **Проверка на статуса:**
  ```cmd
  docker ps
  ```
  *(Или `.\scripts\status_service.bat`. Трябва да виждате `binance_backend` и `binance_frontend` със статус `Up`)*

- **Преглед на логове (при грешка):**
  ```cmd
  docker-compose logs -f
  ```

## 4. Правила за работа с време (Timezone)
Binance API връща време в **UTC**. За да съвпадат графиките 1:1 с локалното време на потребителя (напр. UTC+2 за България), във файл `state.js` се изчислява глобална променлива `TIMEZONE_OFFSET_SECONDS = new Date().getTimezoneOffset() * 60`. 
Тази стойност се добавя към всички идващи свещи (както за историята в `chart.js`, така и за WebSocket-а в `websocket.js`), преди да бъдат подадени на библиотеката `lightweight-charts`.

## 5. Архитектура на проекта (Monorepo)
- `/client` – Frontend (Vanilla JS, HTML, Nginx).
  - `/js` – Модуларен JavaScript код (`state.js`, `chart.js`, `trading.js`, `tabs.js`, `websocket.js`, `main.js`).
  - `/indicators` – Плъгин система за индикатори (`volume.js`, `ma.js`).
- `/services/fetcher` – Python Backend (FastAPI, WebSockets).
- `docker-compose.yml` – Оркестрация на контейнерите.
